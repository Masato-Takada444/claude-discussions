# 経費監査システム - 通知とエラー処理要件

## 1. 通知要件

### 通知タイミング
1. **処理完了時**
   - 件名例：「[TOKIUM経費監査] 監査が完了しました」
   - 内容：
     - 処理日時
     - 処理件数
     - 検出された問題の概要（高リスク：X件、中リスク：Y件、低リスク：Z件）
     - 結果ファイルのダウンロードリンク

2. **エラー発生時**
   - 件名例：「[TOKIUM経費監査] 監査中にエラーが発生しました」
   - 内容：
     - エラー発生日時
     - エラーの概要
     - 処理状況（例：5000件中3000件まで処理完了）
     - 対応方法の案内


### 通知方法
- メール通知（入力時に指定されたメールアドレス宛）
- 複数のメールアドレスへの同時送信に対応

## 2. エラー処理要件

### 基本方針
- **1つのエラーで監査全体を停止しない**
- **エラーが発生した監査観点を明確に記録**
- **他の監査観点は正常に処理を継続**
- **エラー内容を結果CSVに含めて出力**

### エラー時の出力形式

#### 各監査結果列のエラー表示
1. **アルコール判断列**
   - 正常時：「高リスク」「中リスク」「低リスク」
   - エラー時：「エラー」

2. **理由（アルコール）列**
   - 正常時：判定理由の説明文
   - エラー時：「[エラー] AI応答エラー：判定を実行できませんでした」

3. **タクシー判断列**
   - 正常時：「高リスク」「中リスク」「低リスク」
   - エラー時：「エラー」

4. **理由（タクシー）列**
   - 正常時：判定理由の説明文
   - エラー時の例：
     - 「[エラー] 出発地が特定できません」
     - 「[エラー] Google Maps APIエラー：アクセス制限」
     - 「[エラー] 必須項目『出発地』が未入力です」

5. **人跨ぎ重複判断列**
   - 正常時：「高リスク」「中リスク」「低リスク」
   - エラー時：「エラー」

6. **理由（人跨ぎ）列**
   - 正常時：判定理由の説明文
   - エラー時：「[エラー] データ処理エラー：判定を実行できませんでした」

### エラー集計とフィードバック

#### 結果CSVへの情報追加
- 各監査観点ごとのエラー件数をヘッダー部分に記載
- 例：
  ```
  # 監査結果サマリー
  # 総件数: 5000件
  # アルコール監査エラー: 23件
  # タクシー監査エラー: 45件
  # 人跨ぎ監査エラー: 0件
  ```

#### 完了通知メールでの報告
- エラーが発生した場合は、通常の完了通知に加えてエラー情報を含める
- 「一部の経費でエラーが発生しました。詳細は結果ファイルをご確認ください。」
- エラーが多い場合は、データの見直しや再実行を推奨

### エラーからの回復方法
1. **部分的な再実行**
   - エラーとなった経費のみを抽出してCSVを作成
   - 必要な情報を修正後、再度監査を実行

2. **エラー原因の特定支援**
   - エラー理由を具体的に記載することで、ユーザー自身で修正可能に
   - 例：「出発地が特定できません」→ より具体的な地名に修正

### CSVフォーマットチェック
- アップロード直後に必須項目の存在確認を実施
- 不足がある場合は即座にエラー表示（処理開始前）
- 必須項目：経費ID、税込金額、利用日、申請者名、借方勘定科目など
