# TOKIUM AI 経費監査システム Phase2 要件定義書

## 1. プロジェクト概要

### 背景
TOKIUM経費精算で管理される経費データに対して、AI技術を活用した自動監査機能を提供します。Phase1ではGoogle Sheetsベースで実装済みですが、Phase2ではWebベースのシステムとして再構築します。

### ビジネスゴール
1. **最重要**: 監査業務の効率化 - 工数削減
   - お客様が工数削減を実感できるサービス提供
2. **次に重要**: 不正・不備の防止 - コンプライアンス強化

### Phase1からPhase2への移行
- **Phase1**: ローカル環境（n8n）+ Google Sheets + メール送信
- **Phase2**: Webアプリケーション + CSVアップロード + メール送信

## 2. 機能要件

### 2.1 認証機能
- OAuth2認証（TOKIUMアカウントでログイン）
- tokium-agent-travelと共通の認証基盤を使用

### 2.2 監査機能

#### 2.2.1 入力
- **CSVファイルアップロード**
  - TOKIUM経費精算の「経費詳細」フォーマット
  - 必須項目の検証
- **通知先メールアドレス入力**
  - 複数アドレス対応

#### 2.2.2 監査ロジック（Phase1から移植）
1. **タクシー代判断**
   - Google Maps APIで実際の距離・料金を計算
   - 都道府県別タクシー料金との比較
   - リスクレベル: 差額に応じて判定

2. **アルコール判断**
   - GPT-4による支払先・勘定科目・摘要の分析
   - 曜日・時間帯パターンの検出
   - リスクレベル: 低・中・高

3. **人跨ぎ重複判断**
   - 日付＋金額でグループ化
   - 同一人物/異なる人物での重複検出

#### 2.2.3 出力
- **形式**: 元のCSVに監査結果列を追加
- **追加列**:
  - タクシー判定結果
  - タクシー判定理由
  - アルコール判定結果
  - アルコール判定理由
  - 重複判定結果
  - 重複判定理由
  - 総合リスクレベル
- **ファイル名**: 監査実行日時を含む（例: expense_audit_20250107_143000.csv）

### 2.3 データ保存
- 実行者情報
- 実行日時
- 送信先メールアドレス
- 入力ファイル（S3パス）
- 出力ファイル（S3パス）

## 3. 非機能要件

### 3.1 性能要件
- **処理規模**: 
  - 初期: 最大5,000行/回
  - 将来: 最大30,000行/回
- **処理方式**: 非同期バッチ処理
- **処理時間**: 通常5分以内（5,000行の場合）

### 3.2 可用性
- **稼働率**: 95%（平日9-18時）
- **月末月初**: 99%（重要期間）
- **計画メンテナンス**: 月1回、休日実施
- **障害復旧**: 4時間以内

### 3.3 セキュリティ
- **通信**: HTTPS必須
- **認証**: OAuth2（TOKIUM認証）
- **アクセス制御**: 実行者本人のみ（Phase2）
- **データ保持**:
  - 入力・出力CSV: 5年間（電子帳簿保存法対応）
  - アクセスログ: 10年間（仮）

### 3.4 運用・監視
- **ログ保持期間**:
  - アプリケーションログ: 3ヶ月
  - エラーログ: 6ヶ月
  - アクセスログ: 10年
- **エラー通知**:
  - 個別行エラー率50%超過時
  - システムエラー発生時
  - API制限エラー時

### 3.5 エラー処理
1. **個別行エラー**: 処理継続、エラー情報を結果列に記載
2. **システムエラー**: 処理停止、エラーメール送信

## 4. 技術仕様

### 4.1 アーキテクチャ
- **フロントエンド**: React/Next.js（検討中）
- **バックエンド**: Ruby on Rails
- **監査ロジック**: mastra（ワークフロー実装を検討）
- **インフラ**: AWS（Terraform管理）
- **ストレージ**: S3（CSV保存）

### 4.2 外部サービス連携
- **認証**: TOKIUM OAuth2
- **AI**: OpenAI API（GPT-4）
- **地図**: Google Maps API
- **メール**: Gmail API または AWS SES
