# 経費監査システム - パフォーマンス要件

## 1. 処理規模要件

### Phase2（初期段階）
- **1回の監査で処理する最大行数**: 約5,000行
- **月間の監査実行回数**: 約1~2回
- **同時実行ユーザー数**: 最大5人

### 最終目標
- **1回の監査で処理する最大行数**: 約30,000行
- **月間の監査実行回数**: 約5回
- **同時実行ユーザー数**: 最大30人

## 2. スケーラビリティ要件

システムは初期段階から最終目標まで、以下の拡張に対応できる設計とする：
- データ量: 6倍（5,000行 → 30,000行）
- 実行頻度: 2.5~5倍（月1-2回 → 月5回）
- 同時実行数: 6倍（5人 → 30人）

## 3. 処理方式

### 非同期バッチ処理
- CSVアップロード後、バックグラウンドで処理を実行
- 処理完了後にメール通知でユーザーに連絡
- 経費データ入力後すぐに結果を得る必要はない

### 処理時間の想定
- 5,000行: 約10-15分
- 30,000行: 約60-90分
- ※外部API呼び出し数により変動

## 4. 処理における考慮事項

### 外部API利用の課題
- **タクシー料金監査**: Google Maps APIを1レコードごとに呼び出す必要がある
  - 5,000行の場合: 最大5,000回のAPI呼び出し
  - 30,000行の場合: 最大30,000回のAPI呼び出し
  - API制限とコストの考慮が必要

### AI処理の課題
- **アルコール検知**: GPT-4oを1レコードごとに呼び出す必要がある
- **タクシー料金判定**: GPT-4oで料金計算と判定を実施
- 大量データ処理時のレスポンス時間とコストの最適化が必要
