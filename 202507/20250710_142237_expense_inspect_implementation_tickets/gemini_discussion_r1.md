# TOKIUM AI 経費検査システム（Phase2）実装チケット分割の検討

## 背景

TOKIUM AI 経費検査システムのPhase2実装を開始するにあたり、効率的な開発を進めるため、実装内容を適切な粒度でチケット化したいと考えています。

## 現在の状況

### 完了した設計
1. **要件定義**
   - ビジネスゴール：監査業務の効率化（工数削減）
   - 機能要件：CSVアップロード、非同期バッチ処理、メール通知
   - 非機能要件：5,000行処理、5年データ保持、アクセスログ10年保持

2. **技術スタック**
   - フロントエンド：Rails View（MVPではJavaScript不要）
   - バックエンド：Ruby on Rails
   - 監査ロジック：mastra（技術検証が必要）
   - インフラ：AWS（S3、ECS、RDS）、Terraform管理

3. **アーキテクチャ設計**
   - 非同期処理：ActiveJob
   - ファイル管理：S3（inspection_id単位）
   - ステータス管理：accepted → processing → completed/failed

4. **データベース設計**
   - inspectionsテーブルのみ（Userテーブルなし）
   - tokium_user_idで識別（MVP時は固定値）
   - notification_emailsで通知先管理

### MVP方針
- OAuth2認証は実装しない（固定ユーザー）
- 監査ロジックの詳細実装は後回し（インターフェースのみ）
- 最小限の機能から段階的に追加
