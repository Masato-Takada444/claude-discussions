## ■監査ロジックの詳細

<aside>
💡

処理の流れ、プロンプト、条件式、閾値、使っているアルゴリズムなど
**処理の流れ**
１．Google Sheets から経費を取得

1. ロジック適用条件でフィルタリング適用されたもののみ次へ
2. 出発地、到着地の情報からAPIを使って大体の緯度経度を取得し、間の距離（km）および車でかかる時間（分）を算出
3. 全国のタクシー料金表https://docs.google.com/spreadsheets/d/1sc47Dib5E58NUVl8Djd9JlwSYm4npoI_SnPEC_X_YKI/edit?gid=0#gid=0
を持たせたAI1が**出発地の都道府県**をもとに計算し（計算式例↓アルゴリズムにて記載）、経費に登録されている金額と比べ、リスクレベルとともに理由を記述
4. AI2が上記を要約し、Google Sheetsの項目に沿った形で出力
5. Google Sheetsにリスクレベルと判断理由を記載

**プロンプト**

- AIプロンプト
（↑経費IDは消してスプシのrow_numberになる予定です）
    
    あなたは経理監査担当者です。以下の情報をもとに、タクシー料金が相場と比較して不正でないかを判断してください。
    
    計算は各都道府県のタクシー料金体系に基づいて厳密に行ってください。
    
    登録金額と計算金額の差に基づいてリスクを評価し、理由とともに出力してください。
    出力は必ず文字列で返してください！
    また、最後に★★必ず経費ID：{{ $('Google Sheets読み取り１').item.json['経費ID'] }}を出力し★★、200字程度にまとめてください。
    
    【入力データ】
    ・出発地：{{ $json.origin_addresses[0] }}
    ・到着地：{{ $json.destination_addresses[0] }}
    ・距離：{{ $json.rows[0].elements[0].distance.text }}
    ・所要時間：{{ $json.rows[0].elements[0].duration.text }}
    ・登録金額（税込）：{{ $('Google Sheets読み取り１').item.json['税込金額'] }}円
    
    【料金体系（都道府県別に使用）】
    スプレッドシートから「出発地」の該当の都道府県ごとの料金体系を参照する。
    
    【料金の計算方法】
    
    1. 初乗り距離を差し引いた後、加算単位で割って切り捨て → 距離加算金額を算出
    2. 初乗り＋距離加算＋時間加算を合算した金額を「相場金額」と定義する
    3. 以下のルールでリスクを判定：
        - 登録金額と相場金額の差が **1,000円以上** → 「中リスク」
        - 差が **5,000円以上** → 「高リスク」
        - 差が 1,000円未満 → 出力しない（低リスクは無視）
    
    【計算例】
    ■東京都（距離：3.4km、時間：900秒）
    
    - 初乗り：1.052kmまで500円
    - 加算距離：233mごとに100円 → (3400m - 1052m) ÷ 233 ≒ 10回 → 1000円
    - 時間加算：900秒 ÷ 95秒 ≒ 9回 → 900円
    - 合計：500 + 1000 + 900 = 2,400円（相場金額）
    
    ■登録金額：3,600円 → 差額：1,200円 → 「中リスク」
    
    理由：相場金額2,400円に対して登録金額が3,600円と1,200円高く、距離・時間からみても過剰請求の可能性があります。
    
    ## 【出力例】
    判定：～リスク
    判断理由：～
    経費ID：{{ $('タクシー利用判断').item.json['経費ID'] }}
    
    上記のルールと計算ロジックに基づいて、以下の入力データに対し相場を算出し、**リスクが中以上であればその旨と理由を出力**してください。

## ■判定例／サンプル

<aside>
💡

実行結果として出力される監査理由の例

低リスク：登録金額1600円に対し相場金額820円で780円の差額があり、リスクは低リスクと判定されます。

中リスク：相場金額820円に対して登録金額が1,900円と1,080円高く、距離・時間からみても過剰請求の可能性があります。

高リスク：相場金額3140円に対して登録金額が20000円と大幅に高く、距離・時間からみても過剰請求の可能性が非常に高いです。

</aside>

## ■備考／今後の検討事項

<aside>
💡

懸念点、制限、検知の限界、運用ルールなど

- 出発地・到着地の緯度経度をAPIで取得するが、「東銀座駅」など明確な地名であれば正確に位置を特定可能。一方で「神戸」などあいまいな表現だと、APIが広いエリア内の代表地点を返すため、距離や所要時間にズレが生じ、料金の推定が不正確になる可能性があり。そのため、正確な判定をおこなうためには申請者による駅名やビル名など具体的な記載が必須。
- 渋滞に引っかかるとほぼ確実に高リスクと表示される
- タクシーの全国料金表はスプシにべた張りしているだけなので、改定があったら都度変える必要あり

</aside>
